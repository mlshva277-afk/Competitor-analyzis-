# Invest Social Intelligence

Локальный MVP на Python 3.12+, Streamlit, SQLite/SQLAlchemy, Pandas и Plotly.
Сравнивает Selectel с девятью компаниями по каждой площадке отдельно и позволяет
изучать импортированную выборку внешних упоминаний. Реальный сбор соцсетей не включён.

## Запуск

Из корня репозитория:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.lock
streamlit run app.py
```

В подготовленной облачной среде можно использовать уже установленное окружение:

```bash
cd /workspace/Competitor-analyzis-
source /workspace/isi-venv/bin/activate
streamlit run app.py --server.headless=true --browser.gatherUsageStats=false
```

Тесты: `python -m pytest -q`. `requirements.lock` фиксирует проверенные версии
прямых и транзитивных зависимостей; `requirements.txt` описывает допустимые диапазоны.
Python 3.12 проверен в Linux; другие версии Python отдельно не проверялись.

Переменные перечислены в `.env.example`; приложение читает окружение shell,
автоматического чтения `.env` нет. Ключи API для MVP не нужны.
`ISI_DB_PATH` задаёт путь SQLite; по умолчанию `data/invest.sqlite` относительно
каталога приложения. База создаётся при первом открытии интерфейса.

## Первый запуск

Реестр `data/accounts.json` автоматически импортируется идемпотентно:
**10 компаний / 15 аккаунтов / 10 Пульс / 5 Telegram**.
Идентификаторы, роли, исходные и очищенные ссылки, статусы проверки сохранены
из пользовательского файла. Исходный `accounts.csv` также сохранён, но источником
реестра служит JSON. Отсутствующий Telegram-аккаунт означает «не предоставлен».
Проверка `public_preview_accessible` — исходный статус, а не новая проверка сборщика.

Реальная база изначально не содержит постов или статистики. Переключатель
«Демо (demo)» создаёт отдельный файл `invest.demo.sqlite` рядом с реальной базой:
46 синтетических постов (45 официальных и 1 внешнее упоминание), снимки аудитории
и 45 комментариев. Все страницы показывают предупреждение DEMO; ссылки
`example.org/demo/...` обозначают вымышленные материалы. Статистика не является
данными реальных компаний. Метка `dataset=demo` блокирует импорт в реальную базу.
Немаркированный файл проверить на синтетическое происхождение автоматически нельзя.
Демо создаётся один раз; для регенерации остановите приложение и удалите только
демобазу. Процессы сервера не сохраняются между облачными задачами.

## Страницы

- **Обзор**: реестр и число публикаций по датам в выбранной выборке.
- **Selectel vs конкуренты**: снимки аудитории и месячная динамика, частота постов,
  месячное сравнение числа импортированных постов, лидеры и нижняя часть рейтинга.
- **Публикации**: фильтры компаний, площадки, периода, темы, формата и текста;
  ссылки на оригиналы и экспорт выбранной таблицы.
- **Темы и тренды**: несколько тем и форматов у одного поста, месячные распределения.
- **Реакции/комментарии**: метрики, раздельный тон к эмитенту и рынку,
  ручные группы повторяющихся вопросов и ссылки на конкретные комментарии.
- **Источники и качество данных**: импорт, шаблоны, состояния всех 15 аккаунтов,
  журнал успешных и ошибочных операций, ограничения адаптеров.

Общие фильтры задают одну площадку, официальный/внешний тип материала, компании
и период публикации UTC. Месяц сравнения аудитории и месячной активности выбирается
отдельно. Внешние упоминания не объединяются с официальными публикациями.

## Импорт

Откройте «Источники и качество данных», выберите тип и скачайте шаблон.
Поддерживаются CSV UTF-8 (включая BOM, разделитель запятая) и первый лист XLSX.
ID читаются строками. Числа — целые неотрицательные, пустая ячейка — неизвестно.
Нули допустимы только для измеренных нулевых значений. Даты должны содержать
часовой пояс, например `2026-01-10T12:00:00Z`; в БД они нормализуются к UTC.
Время в будущем и наблюдение раньше публикации отклоняются.
`collected_at` — фактическое время импорта, `observed_at` — время измерения.

### posts

Обязательно: `company_id,platform,post_id,source_url,published_at,observed_at,text,kind`.
Для `kind=official` также нужен `account_id` из реестра той же компании и площадки.
Для `kind=external` аккаунт не требуется; `source_url` указывает на внешний материал,
`company_id` — упоминаемую компанию из реестра. Один материал можно импортировать
для нескольких компаний, но результаты сравниваются по компаниям и не являются
уникальным глобальным числом материалов.

Дополнительные поля:

- `reactions,comments_count,shares,views,reach,followers` — метрики на `observed_at`.
  `followers` — аудитория при измерении метрик, не произвольное текущее значение.
- `topics` — несколько меток через `|`: отчётность/финансы, дивиденды,
  корпоративные новости, продукты, кейсы, рынок, образовательный контент,
  мероприятия, репутационные темы. Если поле пусто — локальные правила по словам.
- `formats`: текст, иллюстрации, видео, опрос, карточки; несколько через `|`.
  Если поле пусто — текст; наличие медиа автоматически не определяется.
- `communication_tone`: нейтральный, позитивный, негативный, смешанный,
  не определён. Без ручной разметки — не определён.
- `dataset`: `real` либо `demo`, если указано, должно совпасть с режимом.

Ключ поста: компания + площадка + ID + official/external.
Новый `observed_at` добавляет снимок метрик, тот же — обновляет снимок.
Текст и метки обновляются, время публикации существующего поста менять нельзя.
Таблицы используют последний по времени наблюдения снимок, а не последний импорт.
Экспорт аналитической выборки предназначен для просмотра, не для обратного импорта:
для импорта используйте шаблон, содержащий `account_id` и отдельные поля меток.

### audience

Обязательно: `platform,account_id,observed_at,source_url,followers`.
Только аккаунты реестра. Ключ снимка: аккаунт + `observed_at`.
Подписчики не восстанавливаются из метрик постов и не интерполируются.

### comments

Обязательно: `company_id,platform,post_id,kind,comment_id,text,source_url`.
Сначала импортируйте соответствующий пост. Необязательны `issuer_tone`,
`market_tone` (те же пять значений тональности), `question_topic` (ручная краткая
группа запроса, например «сроки дивидендов»). Без разметки тон не определяется.
Вопросительный знак используется только для отбора кандидатов на ручной просмотр;
это не автоматическая оценка содержательности или тональности.
Повторяющиеся запросы считаются по точному совпадению `question_topic`.

При ошибке отклоняется весь файл, номер строки и причина отображаются в интерфейсе
и журнале. Повторный импорт идемпотентен для данных; журнал сохраняет каждую попытку.
Успешные операции отражаются по аккаунтам, внешние материалы — по площадке;
отклонённые файлы — в общем журнале импорта без ложной привязки к одному аккаунту.

## Как читать показатели

- Месячная динамика аудитории: последний наблюдавшийся снимок выбранного месяца
  минус последний снимок предыдущего календарного месяца. Нет снимка в любом
  месяце — «нет данных». Процент при предыдущем значении 0 не рассчитывается.
  Даты замеров показаны: интервалы между ними могут различаться.
- Взаимодействия = реакции + комментарии + репосты. Если хотя бы один компонент
  неизвестен, сумма и нормированные показатели отсутствуют. Абсолютные реакции
  при этом могут быть известны отдельно.
- На 1000 подписчиков / просмотров = взаимодействия / соответствующий знаменатель
  × 1000. Неизвестный или нулевой знаменатель даёт «нет данных». Охват не заменяет просмотры.
- Рейтинг ограничен одной площадкой, периодом и возрастом поста **при замере**
  (по умолчанию ≥7 суток). Показаны возраст сейчас, возраст при замере, аудитория
  и время наблюдения. Низкая позиция не является оценкой неуспех.
- Количество постов и частота описывают только импортированную выборку.
  0 строк не означает 0 постов на платформе. Изменение размера неполных выборок
  не доказывает изменение реальной активности. Текущий месяц может быть неполным.
- Мультиразметка означает, что сумма постов по темам может превышать число постов.
  Правила классификации прозрачны в `analysis.py`, тональности автоматически не выдумываются.

## Архитектура и ограничения

`storage.py`: восемь таблиц `companies`, `accounts`, `audience_snapshots`, `posts`,
`post_metric_snapshots`, `comments`, `topic_labels`, `source_sync_runs`, внешние ключи
и уникальные ключи снимков. URL, платформа/связанный источник, время сбора и исходные
ID сохраняются. `ingest.py`: валидация и атомарные транзакции. `analysis.py`: расчёты.
`adapters.py`: `SourceAdapter`, рабочий `FileAdapter`, тестируемый `StubAdapter`.

VK API и TGStat API — следующий этап после проверки официальной документации,
условий и пользовательских ключей. Для Пульса, Смартлаба, Альфа-Инвестора и БКС
Профит API и условия пока не исследованы; поддерживается CSV/XLSX fallback.
Заглушки честно возвращают `not_configured`, не фиктивный успех.
Полное покрытие платформ, обход CAPTCHA/авторизации и сбор закрытых данных не реализуются.

OpenAI не вызывается: локальный режим полностью автономен после установки пакетов.
Необязательный API-анализатор — будущая возможность, ChatGPT Plus не даёт API-кредитов.
Приложение предназначено для доверенного локального пользователя: нет авторизации,
многопользовательского разграничения, миграций БД и планировщика синхронизации.
Перед импортом важных данных сохраните резервную копию SQLite при остановленном сервере.
